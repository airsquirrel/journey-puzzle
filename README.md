# 旅程拼图 · 路线规划器

> 输入出发地、目的地、预算和时长，一键拼出一条**可执行**的行程：地图、时间轴、预算分配、他人行程导入，全部在**一个 HTML 文件**里完成。

**在线地址**：<部署后把网址填在这里>

---

## 一句话介绍

把「攻略」变成「路线」：给定预算与时长，自动拼出一份带地图、带时间轴、带花费分配的行程，并且可以把其它 AI 生成的行程文本直接导入成可交互的路线。

---

## 解决什么问题

做旅行规划时，信息是碎的：有人说去哪吃、有人列景点、有人算预算，但这些信息从来不在同一张图上，也无法组合成一条**时间上走得通**的路线。现有产品要么只给攻略，要么只给导航，中间那一步——**把约束（预算 / 时长 / 出发地）变成一条具体行程**——没人做。

本项目就是把这一步做掉。

---

## 核心功能

### 1. 约束驱动的行程生成
- 输入：出发地、目的地、预算（¥200–2000）、时长（24h / 48h / 72h）
- 输出：分天的完整行程，包含交通、景点、餐饮、住宿
- 预算按权重分配（交通 > 住宿 > 餐饮 > 景点 > 医疗），先扣往返城际交通，余额再分配

### 2. 真实数据接入（高德 Web 服务）
- 地点检索：POI 搜索 + 地理编码
- 路径规划：步行 / 骑行 / 公交地铁 / 驾车，按距离自动选方式
- 地图底图：真实瓦片，支持缩放、拖拽、双击复位
- **无 Key 也能用**：默认走「模拟数据」，纯前端随机生成，可完整演示全部交互

### 3. 可拖拽的时间轴
- 横向滚动的卡片式时间轴，按天分段
- 拖动卡片调整顺序，松手后自动重新规划后续路段与时间
- 汇总在途时长、停留时长、交通方式构成

### 4. 导入他方行程（特色功能）
把其它 AI 生成的行程文本整段粘进来，自动解析成可交互路线：

```
07:00 江汉大学出发
地铁3号线 → 关山站换乘1号线
车程约50分钟，票价约5元
08:00 粮道街过早
推荐：丽华早点店（大成路店）
人均：10-20元
09:00 湖北省博物馆
门票：免费
游玩时间：2-2.5小时
```

解析规则：
- 行首 `HH:MM 地点` = 一个站点
- 其后的缩进行 = 该站细节（推荐 / 门票 / 人均 / 游玩时间 / 防坑）
- `Day1 / Day2` 自动分天
- `出发地-目的地：A → B` 提取首尾
- `预估总花费：约280-320元` 同步到预算滑杆
- 费用、停留时长、交通方式与耗时**全部从原文提取**，原文的建议与防坑提示完整保留在详情面板里

### 5. 其它
- 地点评论与图片上传（本地存储）
- 保存路线 / 分享路线（链接内嵌完整路线数据，跨设备可用）
- 街区级地图细节：类型配色、悬停高亮、标签防重叠

> 对应报名表「接口说明 / 测试人员用自己的 API」一栏。

本项目调用**高德地图 Web 服务 API**（POI 检索、地理编码、路径规划），需要一个高德「Web 服务」类型的 Key。

- **测试时请使用测试人员自己的 Key**：打开页面 → 「数据源」选「真实数据」→ 在 Key 输入框填入即可。
- Key **仅保存在本机浏览器的 `localStorage`**，不上传、不写回源码、不发送到任何自建服务器。
- **不填 Key 也能完整测试**：页面默认「模拟数据」模式，无需任何配置即可体验地图、时间轴拖拽、预算分配、行程导入等全部功能。
- 源码中**不含任何 Key**，可自行全文搜索确认。
- 高德个人开发者 Key 免费申请：<https://console.amap.com/dev/key/app>

> 注意：高德个人 Key 的 QPS 较低，真实数据模式下所有请求已做**串行限速 + 限流退避重试**，生成一次约需 7–13 秒，属正常现象，不是卡死。

## 技术方案

| 项目 | 说明 |
|---|---|
| 形态 | **单文件 HTML**，零依赖、零构建，双击即可运行 |
| 代码 | 原生 HTML / CSS / JavaScript（ES5 风格），无框架、无 npm |
| 数据 | 高德 Web 服务 API v3 + v4（POI / 地理编码 / 路径规划） |
| 地图 | 自建 Web 墨卡托瓦片渲染（不依赖任何地图 SDK） |
| 存储 | `localStorage` |
| 分享 | 路线数据 JSON → base64url 内嵌到 URL 的 `#r=` |

### 两个值得一提的工程点

**1. 自建瓦片地图**
没有引入 Leaflet / OpenLayers，而是自己实现了瓦片金字塔：整数级选瓦片、小数级用 `scale(2^(zoom-tz))` 连续缩放、以指针位置为锚点缩放、拖拽平移、比例尺、自动取景。整个地图逻辑约 400 行。

**2. 高德个人 Key 的 QPS 限流**
十多个站点并发请求会直接触发 `CUQPS_HAS_EXCEEDED_THE_LIMIT`，失败的请求降级后会让大量站点落到同一个兜底坐标，地图上表现为「所有点堆在一起」。解决方式：**全局串行队列 + 200ms 保底间隔 + 限流退避重试**，实测 27 次请求 0 失败、14 个站点坐标各不相同。

## 已知限制

- 高德没有高铁班次数据，城际交通用的是综合路径规划，用时仅作参考
- 瓦片来自高德的公开瓦片服务，非官方文档接口，若被策略调整可能失效
- 导入解析是启发式的，依赖「时间戳在行首」的约定；非常规格式会漏解析
- 高德个人 Key 的 QPS 较低，真实数据模式下全部请求串行，生成一次约需 7–13 秒
- 分享链接里的折线会抽稀到每段 ≤20 个点，长路线精度有限
- 导入的路线不携带评论
